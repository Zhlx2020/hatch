# 布局与 ELF

两个只读视图，都在下方抽屉的标签里：`磁盘布局`（顶栏 ▾ 里也有「看磁盘布局」）和 `ELF`（「看 ELF 结构」）。都不需要外部 `readelf`。

## 磁盘布局

构建时 `services/cbuild.py` 与 `services/assembler.py` 会把各段位置记进 `<镜像>.layout.json`，视图只按这份记录分段，再回来对照字节核对：

| 段 | 来源 | 会做什么检查 |
| --- | --- | --- |
| 引导扇区 | 构建记录的第一个 512 字节 | 开头是不是跳转、`0xAA55` 在不在、分区表项、BPB 像不像 |
| 代码与数据 | 构建产物长度 | 加上载入基址，把行号换算成镜像偏移标出来 |
| 填充 | 剩余部分 | 长度是否整扇区、有没有超过软盘容量 |

分区表项存在时整段改称「主引导记录」，逐项报类型、起止扇区和是否可引导。所有结论都是对字节的实际判断，不是猜测。

行号标记来自会话的行映射，和断点用的是同一份数据，所以视图里看到的落点和断下来的位置一致。

## ELF

C 工程链接完成后用 `objcopy -O elf32-i386` 另存一份 `kernel.elf`：地址、节边界与镜像完全一致，只是多了解释性的头和表。`services/elfview.py` 自己解析文件头、程序头和节表，符号交给 binutils 的 `objdump -t`（成熟实现，不重复造），视图逐行渲染。

会标出来的问题：

- 入口地址不在任何可执行节里
- 节同时可写又可执行
- 节对齐超过 64 KB
- 段或节的内容越过文件末尾
- 文件开头不是 ELF 魔数、既没有节表也没有程序头

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/disk` | 当前镜像的分段、字段、行号偏移、告警 |
| GET | `/api/elf` | 当前 ELF 产物（C 工程才有） |

两个都只读，不需要会话处于暂停状态。
