# 0005 工程清单 + C 支持

## 背景

原先只有 `.asm`，靠后缀决定工具链，一个文件就是一个工程。要接 C 就必须知道
「哪个文件是入口、谁去引导、链接脚本在哪」——后缀已经不够用了。

## 决定

- 运行含义写进目录里的 `oslab.toml`（`kind`、`entry`、`sources`、`boot`、`link`），
  由 `services/project.py` 校验；没有清单的裸 `.asm` 还是老路子
- C 走 16 位引导扇区 + 32 位内核 + 链接脚本，产物是平坦镜像
- 链接用 `ld -m i386pe --disable-reloc-section`，`objcopy` 取 `.text/.rdata/.rodata/.data`
- 断点是「行号 → 地址」，构建后才解析，且在执行前写入

## 理由

- 清单比命名约定诚实：模板、示例、用户工程都能改自己的入口和扇区
- 这套 binutils 只有 PE 目标，绕开 `--oformat binary` 是唯一稳的路子
- 行断点必须晚于构建、早于放行，否则第一条语句永远抓不住

## 代价

- 多一个文件要维护，写错了会直接报错（这是想要的）
- 内核限 15.5 KB，够写练习，不够写玩具系统
- 镜像布局和 PE 细节泄漏在 `cbuild.py` 里，换工具链要改这一处
