# 0007 状态改成推送式，QEMU 参数改成模板

## 背景

面板每 700 毫秒要读寄存器、内存、反汇编，而 gdbstub 的读只能发生在客户机停下时。
最开始是「读 → QEMU 自己停 → 没人放开」，客户机被按在 `in al,0x64` 的轮询里，
画面不刷新、键盘也读不到。第一版修法是「按停 → 读 → 放开」，
但只要两路请求撞在一起，`c` 和读的包就会互相穿插，字节流错位，接口 504。

## 决定

1. **一个读线程独占 socket。**`Rsp` 起一个常驻读线程，只负责切帧；命令线程把包发出去后
   在条件变量上等回包。谁都不再直接读 socket，错位这个类别的问题消失。
2. **停机是被推上来的。**`c` 发完即返回，停下来的 `T` 包由读线程回调给会话，
   会话据此翻状态。`/api/state` 变成纯内存读，零 gdb 流量。
3. **运行中不碰 gdb。**寄存器、内存、反汇编显示上一帧停止时的值，跟真调试器一样；
   只有用户主动操作（暂停、单步、翻页、改值）才发命令。
   用户主动读的时候仍然要按停，但那是用户节奏，不是定时器节奏。
4. **QEMU 参数交给模板。**`-m/-M/-boot/-drive/-display/-vga` 由十个测过的
   模板固定（软盘、硬盘、光盘、串口终端、双核、q35、带网卡、冷调试……），
   模板之外的开关走附加参数；写重了直接报「已经由模板管理」。
5. **界面文件 `Cache-Control: no-cache`。**改完 JS 不能还让浏览器用旧副本。

## 代价

- 命令回包的 `T` 和主动停机的 `T` 长得一样，靠「有没有人在等回包」区分；
  为此在 `Rsp` 里加了 `waiting` 计数。运行中恰好有命令在飞时撞上断点，
  那个 `T` 会被当成回包吞掉——测试里没出现过，先这样。
- 运行中寄存器是旧值，得让用户知道这不是实时。界面用「上一帧」的措辞交代。

## 顺带

- 启动按钮旁边加了 ▾：构建并运行 / 只构建 / 软复位 / 重新构建并启动 / 启动设置。
- 串口模板下屏幕那块换成串口文本，界面文案说明「没有画面」。
- 编辑器按扩展名切语言，`.c` / `.h` 用 C 高亮和补全，`.asm` 用 NASM。
