# 0006 行断点与可配置启动

## 背景

断点原先只能在反汇编面板按地址下，看源码时得自己找地址。启动按钮固定「运行」，
QEMU 参数写死在 `process.py`。

## 决定

- 编辑器加一列 gutter，点行号出红点；地址由 `/api/line` 从 `objdump -dl`（C）或 nasm 列表（汇编）解析
- `/api/run` 除了文件名还收 `lines`，服务端在构建后、放行前写断点
- 启动按钮文案/提示/行为（运行或只构建）与 QEMU 的内存、机器、CPU、附加参数进 `workspace/settings.toml`
- 附加参数走白名单，托管项（`-m`、`-display`、`-S` 等）重复就拒绝

## 理由

- 断点是源码级操作，地址应该是实现细节
- 配置要可回滚、可手改，所以是纯文本 + 一个校验函数，不是一堆开关栏
- 白名单挡掉最常见的「加了导致起不来」的错

## 代价

- 红点跟着构建走，改了源码没重新构建时，红点只在下次构建后对应新地址
- 附加参数新特性（比如 QEMU 新开关）要先进白名单
