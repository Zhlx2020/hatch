# 0003 后端换成 QEMU

## 背景

最初的调试后端是 Bochs，走 `-debugger` 加 stdio 管道。实测发现三处硬伤：

1. 客户机运行时调试器不读 stdin，命令只能排队；CTRL_C、CTRL_BREAK 都打不断（两种
   控制台模式都试过，进程还活着但提示符不回）。于是「暂停」无法实现，读状态必然超时。
2. 调试输出是自由文本，寄存器要正则抠，内存要解析 `xp` 的表格。
3. 画面只有 8bpp 3-3-2，端口写死 5900 且绑 `0.0.0.0`，并且只允许一个客户端。

## 对照实测

同一台机、同一个引导镜像：

| 项 | Bochs rfb + 管道 | QEMU vnc + gdbstub |
| --- | --- | --- |
| 异步中断 | 失败 | `0x03` 立刻回 `T05` |
| 寄存器/内存 | 文本解析 | `g` 定长块、`m` 原始字节 |
| 断点 | `pb` 文本 | `Z0`/`z0` 标准包 |
| 像素 | 8bpp，颜色台阶 | 原生 32bpp（shift 16/8/0） |
| 顶底条 | 有，需裁 32+20 像素 | 无 |
| 端口/多客户端 | 固定、单槽位 | 可指定、多客户端 |

## 决定

默认后端换 QEMU，画面走 `display/vnc.py` 原样转发，BGRX→RGBA 放在客户端做。
Bochs 适配器保留在 `backend/bochs/`，接口不变，属于并行后端。

## 代价

- 多了 gdb 远程协议这一层（`backend/qemu/rsp.py`），需要自己做帧与超时。
- gdb stub 没有反汇编器，改为组装时用 objdump 生成静态反汇编表，按地址切片。
- 端口改成 5913/5914/5901 固定，靠启动清理与运行前杀旧进程保证唯一实例。

## 影响

`docs/decisions/0001-bochs-rfb-screen.md` 的部分结论作废：8bpp、裁剪、5900 端口都不再适用。
